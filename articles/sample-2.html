用 GitHub Pages 搭博客：五分钟与零元

不需要服务器。不需要域名费用。甚至不需要懂命令行——如果你愿意花一个下午，就能拥有一个属于自己的写作空间。而且，它是免费的。

这就是 GitHub Pages：GitHub 提供的静态网站免费托管服务。只要你的内容是 HTML/CSS/JS，就能直接上传并获得一个 `username.github.io` 的地址，自带 HTTPS，全球 CDN 加速。

第一步：准备代码（零成本）

GitHub Pages 只吃纯静态文件。你可以：

方案 A（最简单）：直接写 HTML。一个 `index.html` 加一个 `style.css` 就能跑起来，本文的范例博客就是这么做的。缺点是每篇新文章都要手动创建文件。

方案 B（推荐）：用静态网站生成器。比如 Hugo、Jekyll、Astro 或 VitePress。它们能帮你自动生成文章列表、标签页、RSS，还支持 Markdown 写作。Jekyll 甚至是 GitHub Pages 内置支持的。

方案 C（最舒适）：Gatsby 或 Next.js。功能最全，但需要 Node.js 环境和构建步骤。适合有一定技术基础的朋友。

第二步：推到 GitHub（免费）

  1. 注册一个 GitHub 账号（免费）
  2. 新建一个仓库，命名为 你的用户名.github.io
  3. 把你的 HTML 文件 push 上去
  4. 仓库 Settings → Pages → 选择 main 分支 → Save

等一两分钟，你的博客就在 `https://用户名.github.io` 上跑起来了。

如果你不想用 `username.github.io` 这个尴尬的名字，也可以买一个自定义域名（最便宜的每年约 10 美元），然后在 Pages 设置里绑定。这一步不是必须的——免费的子域名已经完全够用。

第三步：持续写作

这才是最难的部分。搭建一个博客，最难的从来不是技术，而是——你真的有东西想写吗？

但如果你有，GitHub Pages 会是最诚实的容器。它不会给你推送算法，不会弹广告，不会记录你的阅读习惯。它只是安静地托管着你写下的每一个字，等着同样愿意花时间阅读的人发现它们。

最后附一句：你正在看的这个博客，就是用这个方案搭出来的。HTML + CSS + 一个 GitHub 仓库，零元，零依赖，永久在线。
